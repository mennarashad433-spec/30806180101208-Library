Task 1: Business Questions & SQL Queries
==================================================

1. How much is each member borrowing?
--------------------------------------------------
SELECT
    m.member_id,
    m.first_name,
    m.last_name,
    COUNT(c.checkout_id) AS total_checkouts
FROM members m
LEFT JOIN checkouts c ON m.member_id = c.member_id
GROUP BY m.member_id;

Explanation:
Used LEFT JOIN to make sure we include members who haven't borrowed any books yet (their count will be 0).


2. Which books match a chosen author pattern?
--------------------------------------------------
SELECT
    book_id,
    title,
    author
FROM books
WHERE author LIKE '%Smith%';

Explanation:
Used LIKE '%Smith%' to search for any authors whose name contains 'Smith'.


3. What are the most popular books?
--------------------------------------------------
SELECT
    b.title,
    COUNT(c.checkout_id) AS times_borrowed
FROM checkouts c
JOIN books b ON c.book_id = b.book_id
GROUP BY b.book_id
ORDER BY times_borrowed DESC
LIMIT 5;

Explanation:
Joined checkouts with books, counted how many times each book was borrowed, and used ORDER BY with LIMIT 5 to get the top 5.


4. Who are the most active readers?
--------------------------------------------------
SELECT
    m.member_id,
    m.first_name,
    m.last_name,
    COUNT(c.checkout_id) AS total_borrowed
FROM members m
JOIN checkouts c ON m.member_id = c.member_id
GROUP BY m.member_id
ORDER BY total_borrowed DESC
LIMIT 10;

Explanation:
Grouped checkouts by member to find who borrowed the most, ordered descending, and took the top 10.


5. What does a neighborhood's activity look like further back in time?
--------------------------------------------------
SELECT
    c.checkout_id,
    m.first_name,
    m.last_name,
    m.neighborhood,
    c.checkout_date
FROM checkouts c
JOIN members m ON c.member_id = m.member_id
WHERE m.neighborhood = 'Heliopolis'
ORDER BY c.checkout_date DESC
LIMIT 100 OFFSET 10;

Explanation:
Filtered by 'Heliopolis' neighborhood, sorted from newest to oldest, and used OFFSET 10 to skip the 10 most recent checkouts.


==================================================
Reflection: Web Page vs. Database API
==================================================

When we get data from a web page (HTML), it is built to be viewed by human users in a browser. The data is wrapped in HTML tags like <table>, <tr>, and <td>, so we have to parse it first using tools like pd.read_html(). Scraped data often has missing values, inconsistent column names, or missing fields (like checkout IDs or return dates in our project).

On the other hand, a Database or API is designed specifically for programs. It serves clean, structured data with strict schemas, correct data types, and primary/foreign keys already set up.

In this task, the Reading Kickoff data came from an HTML page, so we had to extract it, rename the columns to match our main schema, and fill in missing information by merging it with member and book details before combining it with the main database records.
